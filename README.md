# RAGdz

Телеграм-бот, который помогает быстро находить ответы на вопросы по художественным произведениям, не перечитывая текст целиком. Строится на RAG (retrieval-augmented generation): загружаешь текст, бот разбивает его на смысловые куски, строит над ними иерархию саммари и по твоему вопросу достаёт из этой структуры нужные фрагменты, а потом отвечает на их основе.

## Зачем это

Изначально бот задумывался как инструмент для школьников, которые заняты олимпиадами, спортом или другими активностями и из-за этого не успевают вовремя прочитать произведение к уроку литературы (а предмет этот объёмный и времязатратный). С таким ботом можно на перемене закинуть произведение и на самом уроке быстро находить ответы на вопросы, которые возникают по ходу обсуждения.

Но на этом сценарии применение не заканчивается. Бот подойдёт и тем, кто:
- хочет иметь под рукой доказательную базу для споров о произведении (в том числе онлайн);
- хочет вспомнить конкретный момент из любимого текста, не перечитывая его целиком.

Бот сравнительно быстро загружает документы, строит иерархическую структуру над текстом и после этого быстро отвечает на запросы. Качество ответов не идеальное, но для описанных задач его достаточно (подробнее — в разделе [Качество ответов](#качество-ответов)).

## Возможности

- Загрузка собственных текстов в форматах **txt, pdf, docx**.
- Поиск и загрузка текста прямо из **Викитеки** (ru.wikisource.org) — по ссылке на страницу или по названию произведения.
- Личная библиотека (свои загруженные тексты) и общая библиотека (тексты, загруженные другими пользователями).
- Ответы на вопросы по выбранному произведению с сохранением **контекста диалога** — можно уточнять и задавать вопросы по цепочке, не переформулируя всё заново.

### Про загрузку из Викитеки

Вариант удобный, но не идеальный:
- на Викитеке есть не все произведения — в частности, отсутствуют те, на которые нет прав;
- название страницы может совпадать с названием произведения, но при этом быть просто сборником/оглавлением для большого произведения (тома, главы и т.п.) — это стоит проверять самостоятельно перед загрузкой.

### В планах

- Таймлайн событий по конкретному герою или месту.
- Характеристики/описания конкретных героев и мест.
- Устранение технических отказов модели на некоторые вопросы (см. раздел ниже).
- Повышение точности привязки ответа к конкретному эпизоду произведения.

## Как это устроено

### Пайплайн загрузки произведения

1. **Извлечение текста.** `pdf`/`docx` конвертируются в обычный текст, `txt` читается напрямую.
2. **Семантическое чанкование.** Текст режется на предложения, для каждого строится embedding (с учётом соседних предложений), и на основе резкости смены темы (косинусное расстояние между соседними embedding'ами) определяются границы чанков — а не просто нарезка по N символов. У соседних чанков есть небольшой overlap.
3. **Обогащение метаданными и построение иерархии (несколько слоёв "саммари").** Чанки первого уровня группируются батчами и прогоняются через LLM, которая для каждой группы формирует саммари с метаданными: позиция в тексте, заголовок раздела, связь с предыдущим фрагментом, ключевые сущности (персонажи, места, организации, предметы, понятия), временные маркеры. Из этих саммари собирается следующий, более сжатый слой — и так до нескольких уровней иерархии.
4. **Эмбеддинг и сохранение.** И исходные чанки, и все уровни саммари (вместе с метаданными) превращаются в текст и кладутся в векторную БД. Retrieval при этом идёт по всей объединённой структуре ("collapsed tree") — то есть релевантный фрагмент может найтись как в исходном чанке, так и в саммари высокого уровня.

### Пайплайн ответа на вопрос

1. Из истории переписки формируется поисковый запрос к базе (если сообщение одно — используется оно само, если больше — LLM переформулирует историю в один запрос).
2. По этому запросу через косинусное сходство embedding'ов находятся наиболее релевантные фрагменты (исходные чанки и/или саммари).
3. Найденные фрагменты вместе с историей переписки передаются модели, которая формирует итоговый ответ.

### Модели и технологии

- Бот асинхронный, построен на **aiogram**.
- Для embedding и retrieval используется **BAAI/bge-m3** и косинусное сходство (векторная БД — **ChromaDB**).
- Основная LLM — **SberGigaChat**. Также можно подключить любую модель через **OpenRouter**, но с фришными моделями там заметно выше задержка и хуже работает без длинного reasoning — использовать стоит осторожно (если оплачена хорошая модель, пробовать можно).

## Качество ответов

Система тестировалась на нескольких тест-сетах (вопросы с вариантами ответов и с развёрнутым ответом).

- На тестах с вариантами ответов модель в среднем отвечает верно на **9.3 из 10** вопросов — здесь помогает то, что в саммари сохраняются метаданные о времени, действующих лицах, месте и ключевых объектах.
- На вопросах по материалам с учительских форумов (infourok) бот в целом даёт ответы уровня хорошего студента-филолога: глубокие, контекстные, с цитатами и объяснениями. При этом есть проблемы:
  - иногда модель «плавает» между похожими сценами — вероятно, из-за того, что RAG отдаёт приоритет не тому блоку из-за похожих метаданных;
  - в вопросах, требующих назвать одну конкретную деталь, модель иногда уходит в обобщение — возможно, из-за того, что при retrieval'е все уровни иерархии («collapsed tree») загружаются вместе.
- Итоговая оценка ответов (по оценке Claude): **7.91/10** с учётом отказов модели отвечать (отказ = 1 балл) и **8.73/10** без их учёта.

**Известная проблема — отказы GigaChat.** На часть вопросов модель может выдавать отказ со стандартной формулировкой про отсутствие собственного мнения и ограничение обсуждения некоторых тем. Официальный совет GigaChat — снижать «требовательность» запроса — на практике не помогает, рабочего фикса пока нет.

## Установка и запуск

Понадобится **Python 3.10+** (в коде используется современный синтаксис тайпхинтов вроде `str | None`).

1. Клонируй репозиторий:

   ```bash
   git clone https://github.com/ksdfljsdf/RAGdz.git
   cd RAGdz
   ```

2. Создай и активируй виртуальное окружение (по желанию, но рекомендуется):

   ```bash
   python -m venv venv
   source venv/bin/activate  # для Windows: venv\Scripts\activate
   ```

3. Установи зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Скачай данные для NLTK (нужны для разбиения текста на предложения при чанковании):

   ```bash
   python -m nltk.downloader punkt punkt_tab
   ```

5. Заполни `.env` — см. раздел [Переменные окружения](#переменные-окружения) ниже.

6. Запусти бота:

   ```bash
   python main.py
   ```

При первом запуске модель эмбеддингов `BAAI/bge-m3` скачается автоматически (если не указан `EMBEDDING_MODEL_DIR`) — это может занять время и место на диске.

## Переменные окружения

Перед запуском нужно создать файл `.env` в корне проекта со следующими переменными:

```env
BOT_TOKEN=<токен бота из телеграм @BotFather>
GIGACHAT_AUTH_KEY=<ключ к API GigaChat, получить можно тут: https://developers.sber.ru/>
GIGACHAT_CLIENT_ID=<Client ID оттуда же>
OPENROUTER_API_KEY=<ключ к API OpenRouter>

# опционально
EMBEDDING_MODEL_DIR=<путь к локально скачанной модели BAAI/bge-m3, если не хочешь качать её при каждом запуске>
```

Остальные параметры (модель GigaChat, размеры чанков, число результатов retrieval и т.д.) настраиваются в `config.py` и имеют разумные значения по умолчанию — трогать их не обязательно.

## Структура проекта

```
RAGdz/
├── main.py                # точка входа
├── config.py               # настройки, читаются из .env
├── logging_config.py        # настройка логирования
├── clear_library.py         # скрипт полной очистки данных (Chroma + книги + кэш)
├── requirements.txt         # зависимости проекта
├── bot/                     # телеграм-интерфейс (aiogram)
│   ├── main_menu.py          # /start, /menu, /info, главное меню
│   ├── add_file_menu.py      # загрузка файлов и текста из Викитеки
│   └── queries_menu.py       # выбор произведения и диалог с ботом
├── clients/                 # клиенты LLM и внешних API
│   ├── sber_client.py        # клиент GigaChat
│   ├── openrouter_client.py  # клиент OpenRouter
│   ├── wiki_client.py        # клиент Викитеки
│   ├── llm_common.py         # общие схемы/парсинг JSON-ответов LLM
│   └── prompts.py            # системные промпты
├── rag/                     # retrieval-часть
│   ├── chunker.py             # семантическое чанкование текста
│   └── bge_embedder.py        # embedding + работа с ChromaDB
├── data_parser/              # работа с файлами пользователей
│   ├── converters.py          # pdf/docx → txt
│   ├── file_manager.py        # оркестрация загрузки: chunk → summary → embed
│   ├── books/                 # сохранённые тексты (по user_id)
│   └── cache/                 # временные файлы, логи чанкования
└── chroma_db/                # персистентное хранилище векторной БД
```

## Команды бота

- `/start` — приветствие и переход в главное меню.
- `/menu` — главное меню (задать вопрос / добавить произведение).
- `/info` — короткая справка о том, что умеет бот.

## Стек

Python, aiogram, ChromaDB, sentence-transformers / FlagEmbedding (BAAI/bge-m3), NLTK, GigaChat SDK, OpenRouter (OpenAI-совместимый API), pypdf, python-docx, aiohttp.
